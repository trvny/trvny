## Key learnings & principles

### Source feasibility patterns:

Sites behind Cloudflare managed challenge: use Google News RSS proxy (https://news.google.com/rss/search?q=site:\u003Cdomain>&hl=pl&gl=PL&ceid=PL:pl) — returns up to 100 items; filter with site: operator to keep on-domain. Google News titles often include breadcrumb suffixes (strip via regex). Google News site: queries index the whole domain — filter out PDFs, underscore-title fragments, short titles, and known landing pages.

JS-rendered SPAs: check for \\__NEXT_DATA_\\_ (Next.js), window.initials (xHamster), Apollo state blobs, or asset-slug patterns before giving up.

Cloudflare-protected HTML: use curl_cffi with Chrome impersonation (from curl_cffi import requests as creq; creq.get(url, impersonate=\"chrome\")).

Dateless entries: use first-seen timestamp caching (cache survives across runs); assign datetime.now(timezone.utc) rather than date=None to avoid flooding feed cap.

sort_posts_for_feed returns ascending; feedgen reverses on write — keep the tail when capping.

Cloudflare Workers egress: cannot reach other CF-protected origins (still triggers JS interstitial). feeds-proxy Worker does not bypass Cloudflare managed challenges on target sites.

### Feed generator conventions:

main(full: bool) entry point; --full flag resets cache

Per-source error isolation (one failing source never blocks others)

Hash-gated updated timestamps to prevent churn on unchanged entries

Four registry files per new feed: feeds.yaml, README.md, docs/feeds.md, Makefile (optional for pure aggregators)

Literal UTF-8 glyphs in pushed content (— not \\\\u2014) — connector mangles \\\\uXXXX escape sequences

Validate with python3 validate_feeds.py from feedseek/feed_generators/; run as RSS_REPO_SLUG=travino/feeds python3 \u003Cgenerator>.py --full from feed_generators/ directory

multi_rss pattern: multi_rss.run() with SOURCES = \\[(label, url, cap)\\] tuples for native feed aggregation; extra_scrapers callable for HTML sources. High-volume archives should be capped to avoid crowding MAX_ENTRIES.

## Approach & patterns

### GitHub connector workflow:

travino/feeds repo: all files (including Makefile and .github/workflows/) can be pushed normally via the connector. Repo is LF-normalized repo-wide (.gitattributes: \\* text=auto eol=lf). No CRLF exceptions remain — the old \"Makefile is CRLF / deliver as git format-patch / git am --keep-cr\" rule is obsolete.

GitHub connector can write to .github/workflows/ in travino/feeds (Workflows permission confirmed). Push workflow files normally via the connector like any other file.

GitHub:push_files for atomic multi-file commits (no per-file blob SHA needed for new files).

GitHub:create_or_update_file for single-file updates — requires current blob SHA: fetch via git rev-parse origin/main:\u003Cpath> immediately before push.

Always git fetch origin main before pushing shared files (feeds.yaml, README.md) — CI commits every 2 hours and remote drifts constantly.

Post-push integrity: compare md5sum of local file vs curl -fsSL \"https://raw.githubusercontent.com/travino/feeds/\u003Cexact-commit-SHA>/\u003Cpath>\" — use commit SHA not main to bypass CDN cache. diff is more interpretable than md5 when push added doc-comments.

Binary files (PNG, ICO): GitHub connector stores base64 text literally rather than decoding — binary assets must be delivered as ZIP for manual upload via GitHub web UI. Pure SVG (text XML) commits cleanly.

GitHub:delete_file works correctly; does not require blob SHA to be provided.

GitHub:actions_run_trigger with method=run_workflow, workflow_id=\u003Cfilename>.yml, ref=main for dispatch. Poll with GitHub:actions_get → method=get_workflow_run using numeric run ID from workflow_runs\\[0\\].id.

GitHub:get_file_contents is reliable for fetching file content and current blob SHA; avoid tokenized raw.githubusercontent.com URLs (tokens expire quickly).

get_repository_tree with path_filter and recursive: true for scoped tree fetches.

### Cloudflare connector:

D1 provisioning: POST /accounts/{id}/d1/database then POST .../query with SQL. Multi-statement SQL works in single call.

KV and D1 write budgets are shared account-wide (not per-namespace) — D1 preferred for write-heavy use cases (read-state sync).

Real-egress canary pattern: deploy scheduled Worker writing results to KV, poll GET /storage/kv/namespaces/{nsId}/values/{key} with rawBody: true — bypasses sandbox allowlist restrictions.

Cloudflare Worker multipart deploy (when doing it via API rather than wrangler): use rawBody: true, \\\\r\\\\n line endings in boundary separators, metadata part specifying main_module + compatibility_date + bindings.
