# Cloudflare Telegram assistant

- Keep this Worker small and free-tier-friendly; prefer native `fetch` and platform bindings before adding dependencies.
- Reuse the existing `kanarek-companion` free review router through a same-account service binding; do not duplicate OpenRouter/OrcaRouter/AIHubMix adapters or their secrets here.
- Telegram is webhook-driven. Validate `X-Telegram-Bot-Api-Secret-Token` before parsing updates.
- Keep owner-only behavior fail-closed when owner IDs are missing or malformed.
- Preserve durable `update_id` handling around Telegram send side effects; ambiguous delivery must not be blindly replayed.
- Never commit bot tokens, webhook/ingest secrets, API keys, chat session data, or `.dev.vars`.
- Do not add autonomous third-party replies without an explicit approval/draft boundary.
- Reuse the existing Pet Dispatcher control plane for future heavyweight Hermes handoff rather than creating a parallel task transport.
