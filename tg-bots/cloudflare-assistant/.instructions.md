# Cloudflare Telegram assistant

- Keep Worker small, free-tier-friendly; prefer native `fetch` and platform bindings before dependencies.
- Reuse existing `kanarek-companion` free review router via same-account service binding; no duplicate OpenRouter/OrcaRouter/AIHubMix adapters or their secrets here.
- Telegram is webhook-driven. Validate `X-Telegram-Bot-Api-Secret-Token` before parsing updates.
- Owner-only behavior must fail closed if owner IDs are missing or malformed.
- Keep durable `update_id` handling around Telegram send side effects; never blindly replay ambiguous delivery.
- Never commit bot tokens, webhook/ingest secrets, API keys, chat session data, or `.dev.vars`.
- Do not add autonomous third-party replies without explicit approval/draft boundary.
- Reuse existing Pet Dispatcher control plane for future heavyweight Hermes handoff; no parallel task transport.
